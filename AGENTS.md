# AGENTS.md

This repository contains curated Codex skills. Keep its public contract
portable, English, and usable from a fresh clone.

## Repository Boundaries

- A tracked top-level directory containing `SKILL.md` is a maintained custom
  skill. Keep its `SKILL.md`, `agents/openai.yaml`, and directly referenced
  tracked resources consistent.
- `.system/`, `codex-primary-runtime/`, `chronicle/`, and `ci_scripts/` are
  workspace-local or runtime-managed. Do not treat them as repository-owned
  skills or verification inputs.
- `records/`, `archives/`, and `cache/` paths ignored by this repository hold
  private or disposable local data. Do not scan, publish, or migrate their
  contents unless the user explicitly requests that work.
- `xcode-skill-*` directories and `sync-xcode-skills/state/` are generated by
  `sync-xcode-skills`. Never edit generated skills or catalog state directly;
  update the sync workflow and regenerate them instead.
- Local data layout changes belong in `scripts/migrate_skill_data.py`. Keep
  migrations dry-run by default, idempotent, and conflict-safe.

## Working Rules

- Read a selected skill's complete `SKILL.md` before using or changing it.
- Keep long procedures in skills and repository-wide entrypoints here. Do not
  copy private local context into tracked files.
- Describe Xcode workflows in maintained skills by stable evidence capability
  and resolve current tool actions from the runtime inventory. Keep volatile
  namespace or action spelling in executable adapters, runtime configuration,
  or generated upstream content rather than public skill contracts.
- Use English for tracked documentation, metadata, code comments, and
  identifiers unless the artifact itself requires localization.
- Preserve unrelated user changes and keep commits scoped to one coherent
  purpose.

## Verification Contract

The standard repository verification command is:

```sh
bash scripts/verify_repository.sh
```

It validates tracked skill metadata and the README inventory, compiles every
tracked Python file with Python 3.9 or later, syntax-checks every tracked shell
file, runs every tracked `test_*.py` file under a `tests/` or `scripts/`
directory, and runs every tracked `tests/test_*.sh`. Fixture tests are
intentionally excluded from execution.

Add Python tests as `test_*.py` under either `<skill>/tests/`,
`<skill>/scripts/`, or `scripts/tests/` so the standard command discovers
them. Add shell tests as `<skill>/tests/test_*.sh`. The command checks both
staged and unstaged whitespace errors. A
workspace-local `ci_scripts/tasks/verify.sh`, when present, is only a
compatibility delegate; it is not the clone-ready contract.
